## 🛠️ 核心工具

我们提供了一个强大的开发脚本 `scripts/dev-web.sh`：

```bash
# 查看所有可用命令
./scripts/dev-web.sh help

# 最常用的命令
./scripts/dev-web.sh setup    # 首次设置
./scripts/dev-web.sh dev      # 启动开发服务器
./scripts/dev-web.sh check    # 代码检查
./scripts/dev-web.sh deploy   # 部署到 Docker
```

## 💡 核心概念

### Docker vs 本地开发

- **Docker 环境**：生产环境，使用 `docker-compose`
- **本地开发**：开发环境，使用 `pnpm dev`，热重载，快速迭代

### 工作流程

```
修改代码 → 本地测试 → 代码检查 → 构建测试 → 部署到 Docker
   ↓          ↓          ↓          ↓           ↓
 编辑器    localhost   lint/test   pnpm build  docker-compose
          :3000                                 localhost:80
```

## 🆘 遇到问题？

### 快速诊断

```bash
# 检查系统状态
./scripts/dev-web.sh status

# 查看日志
./scripts/dev-web.sh logs web
```

### 常见问题

1. **API 连接失败**？
   - 检查 Docker 后端是否运行
   - 确认 `.env.local` 配置正确

2. **热重载不工作**？
   - 删除 `.next` 目录
   - 重启开发服务器

3. **依赖安装失败**？
   - 检查 Node.js 版本 >= 22.11.0
   - 运行 `./scripts/dev-web.sh clean` 后重新安装

4. **TypeScript 报错**？
   - 运行 `pnpm type-check:tsgo`
   - 根据错误提示修复

更多问题？查看 [故障排查指南](./SAFE_LOCAL_DEV.md#-常见问题排查)

## 🎯 关键提示

### ✅ 要做的事

- ✅ 始终在本地开发服务器测试
- ✅ 提交前运行 `./scripts/dev-web.sh check`
- ✅ 使用 Git 分支开发
- ✅ 编写测试覆盖新功能
- ✅ 更新相关文档

### ❌ 不要做的事

- ❌ 不要直接在 Docker 容器中修改文件
- ❌ 不要提交 `.env.local` 文件
- ❌ 不要跳过 lint 和 type-check
- ❌ 不要在生产环境使用开发服务器
- ❌ 不要直接在 main 分支开发

## 📊 项目配置

### 当前配置

- ✅ Web 服务使用**本地源码构建**（不是官方镜像）
- ✅ 支持完全自定义 UI、文案、样式
- ✅ 前端开发服务器：http://localhost:3000
- ✅ Docker 生产环境：http://localhost

### 系统要求

- Node.js >= v22.11.0
- pnpm v10.x
- Docker 20.10+
- Docker Compose 2.0+
- 磁盘空间 10GB+
- 内存 4GB+（建议 8GB+）
